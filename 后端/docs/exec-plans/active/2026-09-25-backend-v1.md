# Kairos 固定事件后端实施计划

> 执行方式：默认在当前任务中顺序执行，可使用 superpowers:executing-plans 逐项推进；本计划不要求并行代理。以下复选框表示未来实现工作，不是已完成记录。

**Goal:** 完成自然语言录入、澄清、确认保存固定事件，以及到点状态查询和单次请假的可靠后端。

**Architecture:** 单体服务，domain 管时间规则，application 管用例，adapters 管模型和数据库。AI 只生成候选数据，正式写入由确定性校验和事务控制。

**Tech Stack:** 建议 Python 3.12、FastAPI、Pydantic、SQLite、uv、pytest、Ruff、mypy；实际版本由 M1 验证并锁定。

**Spec:** [第一版规划](../../../第一版规划.md)、[架构](../../../ARCHITECTURE.md)、[接口契约](../../design-docs/contracts.md)。

## 全局约束

- 第一版只处理固定事件，不实现柔性任务、Deadline 排序或自动寻找可用时间。
- 事件区间为 [start_at, end_at)，不提前进入事件；跨午夜不触发新一天行为。
- AI 不直接写数据库，确认前无正式事件；普通测试不联网、不使用真实数据。
- 单次请假只影响一个实例；重复规则按原时区展开。
- 当前 API、测试及下列文件均尚未实现；命令是阶段交付后的运行目标。
- 工作目录是后端/；不改动前端源码或根目录已有删除，不自动提交用户原有文件。

## 审查重点及归属

1. 跨午夜和夏令时：M2/M3 验证，不静默移动用户指定时间。
2. 预览到提交之间新增冲突：M4 重查冲突指纹，旧确认不能覆盖新冲突。
3. 两个请求同时确认同一草稿：M4 用两个独立数据库连接验证只保存一批。
4. 已有例外后编辑系列：M3 拒绝危险的时间规则修改，标题修改保留例外。
5. 模型失败或恶意输入：M5 校验不可信数据，已保存事件继续可用。

## 阶段依赖

M1 → M2 → M3 → M4 → M5 → M6。
