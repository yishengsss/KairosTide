# Kairos 新前端设计规范

日期：2026-09-26；状态：设计提案，供评审；没有产品代码、原型或已完成实现。
需求来源：[产品记忆](../PRODUCT_MEMORY.md)；参考证据：[旧代码研读](../CODEBASE_REVIEW.md)。
方法来源：本次已读取 `apple-design/SKILL.md`，采用用户自主权、连续反馈、空间一致性、可打断动效与系统字体原则。

## 1. 设计目标与边界

Kairos 首先是可以安静停留的自然空间。天空、水面与光照承载时间流动，刚性事件在需要时出现，AI 由用户主动打开。
用户应能在不看到钟表的情况下感受到一天推进，同时可靠地创建、确认、查询和处理自己的事件。
成功标准不是信息展示更多，而是自由时无任务负担、到点不漏状态、对话不被打断、操作结果清楚。

- **已确认**：主场景平时没有时钟、时间轴、下一事件、剩余时间、完成率或任务清单。
- **设计建议**：也不常驻显示 FREE 标签，以自然环境表达自由状态。
- **已确认**：自然环境由真实时间、真实天气、季节共同驱动，不能仅切换几个昼夜主题。
- **已确认**：只有刚性事件主动进入主场景；柔性事件保存后隐藏，用户询问 AI 才展示。
- **已确认**：不建独立安排管理页面，不自动分配自由时间，不加午夜总结或开始／结束一天流程。
- **已确认**：旧前端只供参考，新前端重新实现；不直接沿用旧半成品作为产品。
- **已确认（本轮选择）**：自然山水，光照更真实；重点是太阳、天空和水面光照，控件克制。
- **工程建议**：新目录为 `apps/web`，采用 Vue 3 + TypeScript，延续团队经验但重新定义组件、状态和样式。
- **设计建议**：本文所有色值、尺寸、动效参数、布局断点与未决流程的默认方案，均为可评审基线，不是用户已经确认的产品规则。
- **实施边界**：后端能力经审查后才复用；新前端不导入旧前端源码、旧服务适配器或隐含 Demo 行为。

## 2. 视觉方向比较

| 方案 | 画面与交互特征 | 优点 | 代价 |
| --- | --- | --- | --- |
| A 自然山水／湖岸留白（已选方向，湖岸构图为建议） | 广阔天空、远山、近岸与水面；少量浮动功能层 | 太阳轨迹、水面反光、云雨雾雪有一致承载物；信息出现时可保持自然背景 | 要设计横竖屏不同构图与天气遮挡 |
| B 林间天光 | 林木围合、树冠间天空、地面光斑 | 安定与包围感强，季节植被变化直观 | 太阳轨迹容易被遮挡，夜间和密林对比难控制 |
| C 海面与地平线 | 极少陆地、长地平线、天空与海面 | 时间与天气表达直接，宽屏留白充分 | 雨雪与季节差异弱，持续海浪容易分散注意力 |

用户已选择 A 的自然山水与更真实光照方向；B、C 仅保留为取舍分析，不再等待方向选择。
建议以新绘制的湖岸与远景落实该方向，使用更大天空占比。Apple 规范用于交互质量，不将画面变成大面积玻璃拟物。
只借鉴旧 `NatureScene.vue` 的分层思想，不复制山形路径、固定太阳位置或日夜布尔开关。
不沿用旧 `App.vue` 的宣传标题、诗句、多入口和常驻行动号召；产品实际状态替代营销叙述。
不沿用旧 `SchedulePanel.vue` 的问答／固定安排／已安排三标签，事件管理统一放进对话。
不沿用旧 `ActiveEvent.vue` 的时间区间、“正常参加”或仅保存在组件内的冲突选择。

## 3. 布局与空间关系

**建议布局断点**：宽度达到 60rem 用桌面侧面板；低于该宽度用手机／窄屏面板。
主场景占满可视区域，采用动态视口高度与安全区；不以固定最小高度制造页面滚动。
自然场景不因打开面板而跳位或重新生成，功能层叠加在原画面上。
默认只有一个有文字的“问 Kairos”入口和低权重“环境选项”入口，后者容纳查看时间、减少动态和位置设置。
入口不是时钟，始终有键盘可达的等价操作；不依赖悬停才可发现核心功能。

桌面默认／事件状态文字线框：

```text
┌──────────────────────────────────────────────────────┐
│                                      [环境选项]       │
│        连续渐变的天空、太阳／月亮、分层云               │
│                                                      │
│               [仅触发时：提醒／当前事件]               │
│               名称 · 地点                              │
│               对应的操作按钮                           │
│         远山 —— 湖面反光 —— 近岸                       │
│                                         [问 Kairos]  │
└──────────────────────────────────────────────────────┘
```

桌面 AI 打开：右侧留 1rem 外边距，面板宽建议 26rem，上下同样留白，圆角 1.5rem。
左侧自然场景仍可见；AI 是并行工作层，不加全屏压暗遮罩、不缩小场景。
面板从右侧入口方向进入，关闭沿原路退出；对话滚动区与固定输入区分开。
在面板内部顶部预留轻量状态位置，到点后显示一行“高数课正在进行”，可选“回到场景”。
无到点状态时不留空白提示条；插入提示时保持当前输入、焦点与阅读位置稳定。

手机默认／AI 打开文字线框：

```text
默认                          用户打开 AI
┌──────────────────┐          ┌──────────────────┐
│      [环境选项]  │          │ 天空仍可见       │
│ 天空与太阳       │          ├──────────────────┤
│                  │          │ Kairos     [关闭]│
│ [触发时的事件]   │          │ [到点轻量提示]   │
│ 名称、地点       │          │ 对话／澄清       │
│ [知道了] [例外]  │          │ 未保存草稿       │
│ 湖面与近岸       │          │ [确认保存]       │
│      [问 Kairos] │          │ 输入文字  [发送] │
└──────────────────┘          └──────────────────┘
```

手机面板建议最大高度 88dvh；软键盘出现时输入区贴合可视视口，历史消息可滚动。
小高度、横屏或大字号时允许面板充满可视区；不压缩正文，不把确认按钮移到键盘后。
标题可换行，长地点不截断关键信息；事件容器建议宽 `min(30rem, viewport - 2rem)`。
事件位于约 42% 视口高度的低纹理区域，拥挤时以可读性优先，不强求固定中心。

## 4. 自然场景系统

场景渲染接收一个只读 `EnvironmentFrame`，不自行请求天气、不负责事件计算。
输入建议包含真实瞬时、时区、位置精度、太阳高度／方位、月亮参数、天气及来源时间、季节进度、动效偏好。
时间、天气、季节分别计算再组合，禁止“雨天”直接把太阳设成傍晚或切换成夜景。

| 层级（由后到前） | 责任 | 连续驱动方式 |
| --- | --- | --- |
| 0 天空 | 天顶、地平线、暮光与夜色 | 依据太阳高度插值色温与亮度，跨午夜无重置 |
| 1 天体 | 太阳、月亮、星空 | 时间与位置决定轨迹；夜间星光受云量及暮光压制 |
| 2 大气 | 分层云、雨、雪、雾 | 天气改变密度、透射与能见度；云可遮挡正确位置的太阳 |
| 3 远景 | 远山、树林与空气透视 | 雾改变远景对比，季节缓慢改变植被色相 |
| 4 水面 | 天光倒影、太阳反光与雨纹 | 反光跟随光源位置，风雨改变局部纹理 |
| 5 近岸 | 少量植被与稳定空间锚点 | 季节调整覆盖与颜色，避免持续大幅摆动 |
| 6 功能层 | 提醒、事件、临时时间与 AI | 独立控制对比与焦点，天气粒子不覆盖文字 |

工程建议用重新绘制的 SVG／CSS 表达山体、天空与天体，Canvas 表达局部天气与水面光纹；不迁入旧源文件或 assets。
不预先引入整屏 WebGL；用移动端实测决定是否需要更复杂渲染器。
太阳位置按时间连续推进，渲染可以插值；色彩不是按整点突然换色。
天气更新建议在 12 秒内从当前可见状态平滑混合到新状态，不将一次网络返回变成闪屏。
季节建议使用当地年度连续进度，并考虑南北半球；日期变化不能令植被一夜全部变色。
季节不直接等于天气：冬季不能凭日历制造雪，积雪是否模拟需另定数据与规则。
环境变化无需屏幕阅读器逐帧播报，整幅装饰场景从可访问性树排除。

**数据与降级建议**：优先让用户主动选择城市；精确定位是可选操作，不在首次打开强制索取。
位置、天气服务、天文算法和季节映射仍待技术选型，不能称为已经接入真实天气。
天气不可用时继续真实时间驱动，保持中性大气，不伪装晴天为实时天气；环境选项标明天气暂不可用。
可用缓存必须带来源时间与新鲜度；过期阈值由契约定义，前端不隐藏失效事实。
位置未知时提供城市选择；如临时使用近似光照，必须在环境选项标为近似，不宣称准确日出日落。
后台暂停装饰帧，恢复时先重算当前真实状态，再温和衔接；不补播离开期间的动画。

## 5. 长按查看真实时间

**已确认**：在主场景空白区域长按，中央临时显示当前真实时间，例如“14:37”，约三秒后自然淡出。
“三秒”指显示时长；长按判定时长尚未确认。建议判定 600ms，移动超过 10px 即取消。
按钮、输入框、文本选择、AI 面板与事件操作区不触发；失焦、滚动、第二指触摸和 pointercancel 取消判定。
达到阈值时即时读取真实时钟；显示期间若跨分钟，应更新真实时间，不能固定为触发瞬间的过期值。
建议从触发起计 3000ms 后开始 240ms 淡出；180ms 淡入，字号 `clamp(2.5rem, 8vw, 4rem)`。
重复触发可重置显示期限，不积累多个计时器；结束长按不改变当前事件、提醒确认或 AI 状态。
工程测试可注入时间源；用户 Demo 即使加速环境，也必须为这个交互读取独立真实时钟。
提供“环境选项 → 查看当前时间”的键盘等价入口；显示时不移动焦点、不抢占对话播报。

## 6. 提前提醒与正式事件

提前提醒只在规则触发时出现名称、地点、“知道了”，可用文案“稍后有一项安排”。
不显示“还有 N 分钟”、开始时间、倒计时或进度环；“五分钟”只是原始场景示例，不是已定统一配置。
点击“知道了”关闭本次提前提醒；确认状态按具体事件实例及安排版本持久保存，不能当作开始、取消或请假。
点击即撤下当前提醒及增强效果，本地保存待同步操作后异步提交，不让网络延迟阻止关闭。
服务端成功后才标记为已持久确认；失败保持本地已关闭的画面，只给轻量“提醒确认未同步，可重试”提示，不重新弹出催促。
本地待同步记录绑定实例与安排版本；刷新后先恢复该记录并重查当前版本，只对同一有效提醒复用幂等键重试。它不能被当作事件保存、请假或冲突选择成功。
未确认时增强视觉；建议以 `p = 已经过的提醒窗口 / 提醒窗口总长` 的 0–1 值连续驱动。
建议只增强卡片静态边缘对比、局部柔光和阴影：柔光不透明度由 0.04 增至 0.12，最终值封顶。
不增加声音、震动、闪烁、循环呼吸、按钮摇晃或多轮弹出；强度变化本身必须温和。
**待确认**：提前量、确认后是否再提醒、多个提前提醒的处理。建议初始提前量为五分钟，同实例当前安排版本确认后不再提示，明确改期可生成新提醒；均不是用户已确认规则。
多个提醒建议在一个轻量容器内逐项呈现名称和各自确认按钮，不能静默丢弃某一实例。

开始时间到达即在领域状态中成为正在发生；用户没有任何操作，也正常进入。
若 AI 未打开，提醒层自然转为正式事件层，显示名称、地点、“知道了”“例外”。
不保留提醒阶段的“稍后”文案；提前已确认也不能阻止正式事件到点出现。
正式场景建议仅以边缘局部光纹逐渐平静表达经过，无刻度、条形填充、圆环闭合或明确可数单位。
自然场景始终保留真实天气和天体逻辑，事件效果不能改造太阳位置来充当剩余时间指针。
**待确认**：正式事件“知道了”的收起范围。建议收起信息与主要操作，保留低权重“查看当前事件”按钮，可重新展开名称、地点和“例外”。
该按钮至少 44×44 CSS px，可通过 Tab 聚焦、Enter／Space 激活；收起时焦点回到该按钮，展开后不自动抢焦点。
该建议不会把当前事件变成 FREE，也不能复用提前提醒“完整关闭”的状态转换。
**待确认**：“例外”选项。建议提供“这次请假”“取消本次”，在就近小面板说明只影响本次；系列变更通过 AI 对话明确范围。
请求成功后才显示已请假结果；失败保留原事件并可重试；重复事件后续实例保持不变。
正常结束后事件层淡出回自然场景，不出现完成率、庆祝动画或强制总结。

## 7. 冲突与用户选择

同时发生多个刚性事件时，明确呈现各事件名称、地点及选择操作；主场景仍不显示数字时间。
选择前说明：“选择当前展示的事件，其他冲突事件将记为错过。” 不预选第一个，不设默认倒计时。
选择是有语义的领域操作：保存所选实例，以及其他冲突实例的错过记录；不是组件里的暂时高亮。
记录不能删除事件或重复系列；提交失败不显示已成功选择，恢复后必须与服务端一致。
提交需携带用户看到的冲突集合版本；集合变化则要求重新选择，不能将尚未展示的新事件标为错过。
已标错过的实例不会在所选事件结束后自动重新出现；其含义是本次用户选择结果，不是系统验证了实际缺席。
**待确认**：未选择、部分重叠和中途切换规则。建议未选时保持冲突选择层，不自动归为某一事件。
新冲突到来时建议重新呈现受影响选择，并解释已有选择；是否重记错过必须先与领域方案一致。
中途切换建议经 AI 明确表达并预览后果，不默认提供无说明的来回切换按钮。
这些建议在规则确定前只作为设计状态，不应由前端自行实现为最终语义。

## 8. AI 对话、草稿与不中断

单一对话入口承载添加、查询、修改、删除、请假和天气询问；信息卡嵌在对话中，不建立第二套管理导航。
创建刚性事件：表达 → 解析／澄清 → 未保存草稿 → 用户确认 → 服务端保存成功 → 参与事件与提醒。
草稿可显示日期、具体时间、时区、地点与重复规则，隐藏数字时间的约束针对自然主场景，不妨碍用户核对。
“下周二下午上课”缺少准确时间时继续询问；缺地点、重复截止等信息不得由前端自动填造。
多候选结果必须完整保留，逐项可核对；草稿需清楚标记未保存，不以漂亮成功动画掩盖部分失败。
保存失败保留文字和草稿；版本冲突说明数据已变化，用户核对后再提交，避免静默覆盖。
柔性事件由用户主动添加后保存，AI 用保存结果确认；不凭客户端关键词直接生成“建议”替代真实保存。
用户询问可做什么时，AI 才读取已保存柔性事件并结合 Deadline 和当前刚性事件回答，不创造或自动安排任务。
修改／删除的范围与确认策略仍待决定；对系列操作必须明确对象与影响范围，不能使用泛化的“确定”掩盖差异。

AI 打开期间事件到点：只在面板内给轻量提示，不关闭面板、不清空输入、不滚走当前阅读位置、不抢焦点。
领域状态照常推进，场景展示暂缓；草稿、输入、消息、滚动锚点与选择操作各自保留。
建议“完成当前操作”后继续留在对话，由用户关闭或点击“回到场景”进入，避免保存成功成为意外跳转。
**待确认**：操作完成是否自动返回；上述建议比产品记忆更具体，实施前需统一。
关闭 AI 时重新获取当前状态：仍在进行则显示，已结束则回自由场景，不重播已结束事件。
到点冲突也只用轻量提示；回到场景后才要求选择，不在输入中途强制呈现冲突弹层。

## 9. 字体、材质与动效参数

字体建议 `system-ui, -apple-system, BlinkMacSystemFont, "PingFang SC", "Microsoft YaHei", sans-serif`，不要求下载品牌字体。
正文 1rem／1.6、权重 400；事件标题 `clamp(1.5rem, 3vw, 2.25rem)`／1.25、权重 600；辅助文字最低 0.875rem／1.5。
中文正文字距 0；大拉丁标题可 -0.02em；不使用大面积细字或散开的装饰性英文。
尺寸与间距用 rem，支持 200% 缩放；触控目标建议至少 44×44 CSS px，相邻操作留 8px 间距。
浅色面板建议 `rgba(248,250,246,.92)`、正文 `#172920`；深色建议 `rgba(18,29,26,.94)`、正文 `#F4F7F4`。
面板 blur 20px，卡片 blur 12px，边界 1px，阴影基线 `0 12px 40px rgba(0,0,0,.12)`；大面板圆角 24px、小卡 16px。
单个区域只保留一层主要透明材质，内部草稿用近实色底；不在玻璃上再叠薄玻璃。
配色须对真实合成背景测量：正文至少 4.5:1、大字至少 3:1、控件和焦点指示至少 3:1；不能凭色值表宣称通过。
键盘焦点建议 2px 实线外框加 3px 间距；不以颜色单独区分草稿、保存、错误和冲突。

| 交互 | 建议参数 | 中断／降级 |
| --- | --- | --- |
| 按钮按下 | pointerdown 立即着色；缩放到 .98，响应 80ms | 移出取消提交；降低动效只保留着色 |
| 桌面 AI 面板 | 位移 24px + 透明度；临界阻尼 1.0，response .32s | 从当前显示值及速度重定向，不能等待退出完再打开 |
| 手机面板 | 位移 32px + 透明度；阻尼 1.0，response .36s | 首版显式按钮关闭；若支持拖动必须 1:1 跟手并传递释放速度 |
| 提醒／事件出现 | 位移 8px，透明度 0→1，320ms，cubic-bezier(.2,.8,.2,1) | 状态改变立即重定向；不排队等待整段动画 |
| 事件结束 | 当前透明度→0，400ms ease-out | 新事件出现从可见状态衔接，禁止空白闪跳 |
| 天气参数混合 | 12000ms 连续插值，从当前环境参数开始 | 新天气覆盖目标而非叠加队列；降低动效用静态天气纹理 |

response 是弹簧响应参数，不是保证结束时长；实现使用的库需明确参数映射，不能把 damping ratio 直接当 damping 常数。
建议首版不加面板拖拽关闭，减少误关闭草稿；若后续增加，位移阈值 10px、边界阻力系数 .55、关闭始终可撤回到未提交状态。
可交互动画不锁输入；页面关闭／卸载清理动画与监听；改变偏好时不要求刷新。
普通位移动画只动 transform／opacity，避免每帧改变布局、模糊半径或大面积阴影。
不做全景相机移动、呼吸缩放、循环耀斑；云与水仅局部低幅变化，渲染预算应由移动端测试约束。
`prefers-reduced-motion`：停雨雪粒子与环境循环，保留真实位置和静态天气；交互改 120ms 淡入淡出，无缩放／滑移／弹簧。
降低动效时天体可降低更新频率但仍由真实时间计算；提醒用静态边框对比增强，不能取消提醒含义。
`prefers-reduced-transparency`：面板改不透明，无 backdrop blur；`prefers-contrast: more`：实色底与清晰边界。
若浏览器不支持这些偏好查询，环境选项提供对应设置；不要把透明材质作为唯一层级提示。
读屏使用克制的 polite 状态播报，到点只播报一次；错误就近说明，装饰变化不播报。

## 10. 组件职责与 Harness 验证接口

| 建议组件／模块 | 职责 | 禁止承担 |
| --- | --- | --- |
| AppShell | 视口、安全区、功能入口、面板结构 | 自然语言意图判断、时间规则 |
| NatureScene | 渲染 EnvironmentFrame 与分层景物 | 获取天气、保存事件、决定冲突 |
| EnvironmentController | 合并真实时间、天气、季节与偏好 | 更改事件开始时间 |
| TimePeek | 空白长按、真实时间、消失期限 | 使用 DemoClock、改变事件状态 |
| ReminderLayer | 展示实例提醒，发出确认意图 | 猜提前量、把确认变成请假 |
| ActiveEventLayer | 正式事件信息和操作入口 | 用组件本地值当出席事实 |
| ConflictChoice | 展示冲突与选择后果 | 自动选择或删除未选事件 |
| AssistantPanel / DraftReview | 消息、输入、澄清、候选核对与保存意图 | 把未确认草稿发布为事件 |
| PresentationCoordinator | 区分领域状态与暂缓展示，关闭 AI 后重算展示 | 延后实际事件或排队重播旧事件 |
| ApiBoundary / SessionStore | 版本、幂等、同步状态、输入和草稿恢复 | 丢弃实例例外、静默模拟成功 |

Harness Engineering 建议：提供确定性状态夹具与独立预览入口，生产默认入口不能意外进入演示模式。
需求映射：K02 对应自然主场景，K03 连续太阳，K04 天气季节，K05 真实查时，K06 提前提醒，K07 正式事件，K09 冲突，K13 对话不中断，K16 可访问性。
夹具覆盖时间、天气、季节、事件实例、冲突、提醒确认、AI 打开和降低动效；真实查时测试使用独立时间源。
组件接收显式输入，测试不依赖真实 AI 随机回答或网络天气；接口联调另设真实契约验收，不能用夹具替代。
关键状态使用稳定语义定位和最少量 test id；保存视口、夹具、偏好、截图与动作记录，便于复现设计问题。
领域真实状态和展示状态分别可观察，日志不得记录对话全文或位置细节作为默认调试手段。
只复用已验证契约与能力，不把旧 Demo 通过当成新产品验收证据。

## 11. 必须能演示的验收情景

| 情景 | 可核验结果 |
| --- | --- |
| 自由状态停留、跨午夜 | 自然连续变化；无钟表、列表、下一事件、午夜弹层 |
| 同一下午时刻晴转雨 | 太阳保持正确位置，云雨与水面变化，不错误变成夜景 |
| 横竖屏、320px 窄屏、200% 字号 | 事件和输入可操作，安全区完整，长标题与地点可读 |
| 长按／移动取消／Demo 加速 | 空白长按显示真实时间约三秒；移动取消；不显示模拟时间 |
| 提前提醒确认与不确认 | 确认关闭本次；不确认增强视觉且封顶；均无数字倒计时 |
| 已确认提醒到点 | 正式事件仍出现，无额外“开始”步骤，结束后自然消失 |
| 重复事件这次请假 | 只影响本次，失败可重试，后续系列不变 |
| 多事件冲突 | 无默认选择；后果清楚；选择与错过状态经服务端确认 |
| AI 输入／草稿期间到点 | 仅轻量提示；输入、草稿、焦点、滚动位置保持 |
| AI 关闭时事件已结束 | 回自然场景，不播放过期事件或补播一串提醒 |
| 缺时间与多候选草稿 | 继续澄清、不编造；全部候选可核对；未确认不触发提醒 |
| 柔性事件添加与询问 | 保存后主场景隐藏；主动询问才能显示真实已保存任务 |
| 连续开关面板、动效中再次点击 | 动画从当前可见状态重定向，无锁输入、闪回或丢草稿 |
| 断网／恢复、天气过期、后台恢复 | 保留输入，数据状态诚实；重算当前状态，不误复活请假实例 |
| 降低动效／透明度／提高对比 | 含义完整、文字可读、操作不依赖移动背景或透明度 |

上述验收是待执行的设计门槛。当前没有浏览器截图、交互原型、性能数据或可访问性通过结论。
进入实现前应统一提醒策略、正式知道了、例外范围、冲突规则、位置与天气降级、AI 完成后返回策略；视觉参数可在可运行新前端中验证后调整。
