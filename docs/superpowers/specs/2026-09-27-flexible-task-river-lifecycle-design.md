# 河面柔性任务信号与生命周期设计

状态：待用户审阅的设计提案。用户已确认的产品要求单列于“已确认行为”；接口与状态模型是待批准的工程方案，不代表已实现。

## 目标与范围

已保存的柔性任务可通过河面的黄色圆环被用户发现和选择。圆环不替用户排期；用户点击任务、选择接受后才进入持续显示的进行中状态。刚性事件红圈和黄色柔性任务圈使用同一水域布局，可同时出现且不重叠。

本设计包括事件信号布局、柔性任务详情卡、接受/暂停/完成交互、任务状态持久化、API 契约与迁移、预览和验收。天气、AI 自动排程、任务提醒、刚性事件领域规则不在范围内。两个旧半成品继续保持只读，不作为运行时或依赖。

## 已确认行为

- 红色刚性事件圈和黄色柔性任务圈都在动态水线下方随机位置出现；可有多个黄色圈；任何圈之间不得重叠。
- 黄色圈出现时不显示标题、提示文案、通知或其他提醒。用户点击黄色圈后才打开任务详情。
- 每次未接受的黄色圈随机显示 5–10 分钟。打开详情不暂停计时；计时到期时圆圈消失。
- 用户点击“接受”后，该任务的黄色圈持续显示，直到用户再次打开详情并选“暂停”或“完成”。
- 详情打开期间计时照常运行；圆圈到期不强制关闭已经打开的详情。
- 选择“暂停”时，进行中圆圈立即消失，任务仍保留在规划列表。它回到待选择状态，未来仍可作为随机黄色圈再次出现。
- 选择“完成”后，任务记录完成状态且不再生成圆圈。
- 用户再次明确确认：红圈和多个黄圈都在实时水线下方随机选位、彼此避让；空间不足时先不放新圈。黄圈出现不伴随任何提醒；每个未接受任务每次显示 5–10 分钟随机时长；生命周期状态须由后端持久化；预览页须能检查多圈避让和状态操作。

## 推荐状态与数据流

任务状态由后端持久化，避免页面刷新或设备会话结束后丢失“接受／完成”状态。公开状态使用 `planned | active | completed`：

| 状态 | 场景表现 | 进入方式 | 后续变化 |
| --- | --- | --- | --- |
| `planned` | 不常驻；随机获得限时黄色圈 | 新建任务、临时圈到期、用户选择暂停 | 圈可再次随机出现；用户选择接受进入 `active` |
| `active` | 黄色圈持续存在 | 用户在任务详情明确选择接受 | 点击圆圈打开详情；选择暂停回 `planned`，完成进入 `completed` |
| `completed` | 不显示圆圈，不进入随机候选 | 用户在进行中任务详情选择完成 | 保留为完成记录，不再自动回到待选状态 |

临时黄圈与5–10分钟的到期时刻属于前端展示状态，不写成任务计划时间，也不改变后端任务状态。限时圈到期或暂停不会删除任务。接受、暂停、完成通过用户直接点击提交，不经过 AI；服务端按任务所有权、当前版本与允许的状态转移校验，并要求幂等键。状态变更失败时保留当前详情、显示可恢复错误，不谎报成功。

列表 API 返回生命周期状态，以便规划列表保留待选、进行中和完成记录。随机候选只选择 `planned`；已接受圈由服务端状态恢复。AI 工具不增加新的状态写权限，现有查询需将状态作为任务数据如实呈现。

建议为任务 API 增加按 task ID 的状态变更操作，负载包含目标状态和 `expected_version`，响应返回最新 task 与 version。SQLite 迁移为既有任务设置 `planned`，每次有效转移递增版本。使用 owner-scoped 服务用例执行，不让前端直接写数据库，也不允许模型伪造任务状态变更。

## 圆圈布局与交互

- 场景每帧提供实际波形的水线取样；每个圈保留自己的随机横向位置及水线下偏移，随该位置的水线真实升降。
- 新圈只从水域边界内的候选位置采样；用圆环实际半径加安全间距检测与现有红圈、临时黄圈、进行中黄圈的碰撞。既有圈保持位置稳定，新圈重抽位置直至无重叠。多枚临时黄圈可各自持有独立 5–10 分钟寿命。
- 若当前视口没有足够的合法空间，不强行叠圈或放到岸上；暂缓新的临时圈，直到空间可用。窗口缩放时优先保持进行中圈，不重置随机计时。
- 黄色临时圈可点击并可键盘聚焦。打开详情显示任务名称、截止信息（若有）及“接受”；即使此时计时到期，已打开详情仍保留，接受动作仍有效。
- 进行中黄色圈点击后打开同一任务详情，提供“暂停”和“完成”。暂停/完成成功后详情关闭且圆圈移除；失败则保留详情及重试入口。
- 任务的被动展示节奏继续使用已确认的低频 cadence（FREE 下随机 45–90 分钟、每小时最多一次）。每次到达时按可用空间从 `planned` 任务中随机放入多个新黄圈；每个圈独立抽取 5–10 分钟寿命，到期各自消失。助手打开、提醒/冲突存在或页面隐藏时不生成新临时圈。活动红圈不取消已经显示的黄圈。

## API、故障和迁移

- 给柔性任务 DTO 增加 `lifecycle_status`，读写都基于 owner-scoped task ID。
- 新增状态变更用例与 HTTP 操作，验证 `planned → active`、`active → planned`、`active → completed`；拒绝所有未列出的转移、过期版本、跨用户 ID 和不匹配的幂等重试。
- SQLite 迁移为旧记录补 `planned` 默认值；列表、助手查询和 Web 生成契约同步状态语义。完成记录仍可查询，但不参加随机候选。
- 后端离线/状态请求失败时不把临时圈当成已接受、暂停或完成。限时圈到期是本地呈现结果；下一次服务端同步仍以持久任务状态为准。
- 详情内有网络错误时保留操作上下文和按钮重试；重复提交同一个 idempotency key 返回同一结果。

## 验收

- 领域/API：迁移旧任务为 `planned`；覆盖合法/非法状态转移、owner 隔离、版本冲突、幂等重试；暂停任务仍在规划列表，完成任务仍可查询但不再进入候选。
- 前端状态：可注入时钟验证每个临时圈独立使用 5–10 分钟时长；打开详情时计时继续；到期只移除圈且保留已开详情；接受后跨刷新恢复；暂停立即消圈并保留任务；完成后不再出现。
- 布局：有一个红圈、多个已接受黄圈、一个临时黄圈时，所有圈位于实时水线下且互不重叠；桌面、390px 手机、320px 窄屏及 resize 下空间不足时不压叠、不越过岸线。
- 交互：黄圈出现前无文案/通知；鼠标、触屏与键盘可打开详情并提交；红圈/黄圈可并存；减少动态效果下位置仍静止且可操作。
- 验收证据须区分代码/API 通过与真实浏览器视觉/旅程结果；Harness 的 `e2e` 未运行时不得声称端到端通过。
