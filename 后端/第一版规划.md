# Kairos 第一版后端规划

## 1. 目标与范围

第一版打通「自然语言录入 → AI 解析 → 必要澄清 → 保存固定时间事件 → 到点进入事件 → 结束恢复自由」的闭环。

AI 理解用户已经表达的安排，不替用户选择空闲时间或自动生成日程。固定事件包括课程、会议、考试、预约等具有明确起止时间的安排。

第一版不包含柔性任务、Deadline 排序、任务拆解、自动推荐、番茄钟、完成率统计、开始一天或结束一天。识别到「找时间复习」等柔性任务时，说明当前只支持固定时间安排，不擅自分配时间。

## 2. 技术建议与现状

当前目录已有 Python 虚拟环境与 SQLite 路径配置示例，未发现业务源代码。建议采用 Python + FastAPI + SQLite；这是待实现方案，不表示现有功能已完成。

- AI 接口封装为独立适配器，供应商、模型、密钥由服务端环境变量配置。
- 数据库路径沿用 KAIROS_DB_PATH，默认 .data/kairos.sqlite3。
- 初版以单用户本地运行作为规划假设；公网服务与多用户账户不在本轮范围。
- 事件判断、时区换算、重复展开、异常处理由确定性程序执行，不能依赖模型自由生成。

## 3. 自然语言录入流程

1. 接收原文、用户时区、解析请求标识；以服务端当前时间作为相对日期的参照。
2. AI 返回结构化候选事件或澄清问题，不直接写入数据库。
3. 校验字段、时间顺序、日期、时区、重复范围与冲突。
4. 缺少日期、起始时间或结束时间/时长时追问；存在多个合理解释时让用户选择。
5. 返回事件草稿，前端展示可编辑的安排摘要。
6. 用户确认后，通过提交接口保存；重复提交同一标识不得产生重复事件。

示例：「明天下午两点开项目会，一个小时，在会议室 A」可形成完整草稿。

示例：「周五下午上课」缺少明确起止时间，需要追问。

示例：「每周一 14:00 到 15:40 上数据结构，这周一请假」先形成重复规则，再对指定日期建立例外；若“这周一”已过去，明确告知解析日期并等待确认。

初版支持创建、查看、表单修改/删除、单次请假与取消。自然语言修改已有事件、复杂跨事件指令暂不纳入第一版。

## 4. 时间与重复规则

- 默认时区取客户端系统设置，并允许在设置中修改；不得根据语言猜时区。
- 单次事件保存 UTC 起止时刻，同时保留原始 IANA 时区。
- 重复事件按原始时区的本地时间展开，初版仅支持每天、每周指定星期；可设置结束日期或持续重复。
- 不支持的复杂重复规则需明确说明或请用户简化，不能静默近似。
- 跨午夜事件必须保存明确的结束日期；起止关系不合理时不写入。
- 夏令时导致不存在或重复的本地时刻时要求澄清。
- 相对日期在解析时固定，草稿确认前若已明显过时，重新提示校验。
- 两事件重叠时返回冲突详情；不自动挪动原事件，允许用户修改或明确保留冲突。
- 查询仅展开有限日期范围，避免无限重复事件全量生成。

## 5. 数据模型

### Event：事件或重复系列

- id、title、location、notes
- timezone
- 单次事件：start_at、end_at
- 重复事件：local_start_date、local_start_time、local_end_time、end_day_offset、frequency、weekdays、until_date
- version、created_at、updated_at

### EventException：单次例外

- id、event_id、occurrence_key
- type：excused（请假）、cancelled（取消）
- created_at

occurrence_key 必须稳定标识重复系列中的某一次，例如原始时区下的计划开始日期时间；请假不能影响整个系列。

### Draft：录入草稿

- id、source_text、timezone、reference_now、candidates
- clarification、revision、expires_at
- status：needs_clarification / ready / committed

### Occurrence：接口派生出的事件实例

- occurrence_id、event_id、title、location、start_at、end_at
- status：scheduled / active / finished / excused / cancelled

scheduled、active、finished 根据服务端时间与例外推导。active 表示处于计划时段，不代表真实到场；未操作默认按计划进入，不记录为已验证出席。

## 6. 前后端接口约定

API 前缀为 /api/v1，JSON 字段使用 snake_case。时间戳使用含时区偏移的 ISO 8601；接口实例统一输出 UTC。

| 方法与路径 | 用途 | 核心字段 |
| --- | --- | --- |
| POST /event-drafts | 解析自然语言 | text、timezone、request_id |
| POST /event-drafts/{id}/clarifications | 回答澄清问题 | answer、revision |
| PATCH /event-drafts/{id} | 编辑候选安排 | candidates、revision |
| POST /event-drafts/{id}/commit | 确认保存 | revision、idempotency_key、allow_conflicts |
| GET /events | 管理页列出事件/系列 | 分页参数 |
| GET /occurrences | 查询有限窗口内实例 | from、to |
| GET /state | 同步当前状态 | 返回 server_now、active_occurrences、next_transition_at |
| PATCH /events/{id} | 修改单次事件或整个系列 | version、更新字段 |
| DELETE /events/{id} | 删除单次事件或整个系列 | version |
| POST /occurrences/{id}/exceptions | 本次请假/取消 | type、idempotency_key |

草稿接口返回 draft_id、revision、status、candidates、questions、conflicts。提交成功返回 event_ids。冲突允许仅在用户明确选择后设置 allow_conflicts。

统一错误格式：code、message、field_errors、retryable、request_id。模型超时、无效结构、日期不合法、版本冲突分别返回可处理错误，不保存半成品。

## 7. 到点状态与恢复

- 当前时刻满足 start_at ≤ now < end_at 且无例外的实例为 active。
- 固定事件到点才进入前台；后台 next_transition_at 仅供同步和定时使用，不展示倒计时。
- 多个 active 实例同时返回，前端呈现冲突选择，不让后返回的事件静默覆盖前一个。
- 请假后重新计算当前有效实例；没有其他有效实例则回到自由。
- 页面刷新、设备唤醒、网络重连时重新同步 /state，不能只依赖页面计时器。
- 错过完整时段的事件不补弹；仍处于事件时段内则进入当前事件。
- 第一版不承诺浏览器关闭或系统休眠期间的通知；系统通知/后台运行属于后续能力。

## 8. 模块与实施顺序

建议模块：api（路由）、schemas（输入输出校验）、ai（模型适配）、events（业务规则）、schedule（时区与重复）、storage（持久化）、tests（关键行为）。

1. 建立数据库、事件 CRUD、实例展开及 /state；使用固定测试数据跑通时间行为。
2. 接入 AI 结构化解析、草稿、澄清与提交。
3. 完成重复事件、单次例外、冲突提示和幂等保护。
4. 与前端联调录入、到点、结束、刷新与重连。

## 9. 验收标准

- 一句话可以创建明确的单次固定事件，确认前不写入正式事件表。
- 每周课程能按指定时区正确生成实例，本次请假不影响下一周。
- 模糊时间会追问，柔性任务不会被偷偷排入日程。
- 重叠事件得到明确提示，未经选择不自动调整或忽略。
- start_at 到点生效、end_at 到点结束；跨午夜、刷新和唤醒保持一致。
- 模型故障不影响已保存事件的时间判断。
- 重复提交不会重复创建事件；失败不会产生部分写入。
- API Key 不发送到浏览器，日志避免记录密钥及不必要的完整用户原文。
