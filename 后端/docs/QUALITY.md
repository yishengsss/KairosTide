# 质量与反馈门禁

2026-09-25：文档、M1/M2 基线及 M3/M4 主要流程已建立。冲突预览确认和真实模型在线评估尚未完成；质量账本列出已运行证据。

## 分层验证

| 层级 | 检查内容 | 失败时行动 |
| --- | --- | --- |
| 文档 | 内部链接存在、状态及契约一致 | 修正文档再开始对应任务 |
| 静态 | Ruff、类型检查、架构导入规则 | 修实现；不能删检查来通过 |
| 单元 | 固定时钟下的边界、重复、冲突、例外 | 最小输入复现并加入回归 |
| 集成 | 临时 SQLite、事务回滚、重试、HTTP 契约 | 保存请求及错误码的脱敏证据 |
| AI 离线 | 假 Planner、无效模型输出及攻击性文本 | 校验不可信输出的失败路径 |
| AI 在线 | 同一评估集在具体模型上的结构与语义 | 更新提示词版本并记录退化 |
| 端到端 | 录入→澄清→确认→到点→请假→结束 | 对照产品验收检查状态变化 |

## 关键行为矩阵

- T01：开始前 1 微秒无 active，开始时 active，结束时不 active。
- T02：Asia/Shanghai 周一课程，本次请假后下一周依旧有效。
- T03：跨午夜事件能在第二天查询范围内出现；相邻事件不冲突。
- T04：America/New_York 的不存在/重复时刻必须按已确认策略处理。
- T05：冲突预览后新增另一事件，旧确认不能直接提交。
- T06：连续重复提交及两连接竞争提交，最多产生一组事件。
- T07：写入第二个候选时失败，首个候选、例外和草稿状态全部回滚。
- T08：AI 超时/无效字段不产生正式事件，已有 /state 仍可查询。
- T09：跨本地午夜回答澄清，reference_now 不被新请求覆盖。
- T10：有例外的系列改时间被拒绝，改标题不破坏例外。
- T11：未来超过冲突窗口的重复系列明确标注检查范围。
- T12：提示词中要求泄露密钥或跳过确认不改变写入权限。

## 目标检查入口

从后端目录执行，以下离线命令已实际运行并通过：

```sh
uv sync --locked --dev
uv run ruff check .
uv run ruff format --check .
uv run mypy src
uv run pytest -q
uv run python scripts/check_docs.py
```

M6 增加 OpenAPI 重新生成与差异检查。CI 运行同样的离线命令；没有模型密钥也必须通过。在线评估单独报告，不能因未运行就记作模型功能通过。

## 完成定义

1. 对应用户行为有测试；新测试先观察到与行为相关的失败，再通过实现修复。
2. 相关静态、单元、集成检查实际通过，并记录执行目录、命令、结果及代码版本。
3. 契约及生成产物与实现一致，质量账本写明仍缺什么。
4. 没有真实数据或密钥出现在提交及测试输出中。
5. 完成一个阶段后更新执行计划；不以文档数量、测试数量或覆盖率单独判定完成。

## 维护节奏

每次修改接口或业务规则时同步更新文档；每个里程碑结束时检查失效链接、过时命令、重复规则及未闭环失败。先用失败证据定位缺失的环境、规则或工具，再做最小修复。不创建定时自动化，也不自动开启外部通知。
