# 课表图片转刚性日程草稿

## 状态与范围

用户已确认第一阶段目标：上传一张课表图片，由多模态 AI 智能分析并生成待确认清单；图片涉及的日期内可只读查询当前用户的刚性日程以辅助去重/冲突展示；任何新日程仍由用户检查并确认后才保存。

本阶段是单图到草稿的端到端切片：前端附件、API 图像校验、MiMo 多模态输入、结构化多事件提取、重复日期澄清、刚性事件查询、确认清单和最终提交。暂不支持 PDF 或多图合并；旧项目保持只读参考，不作 runtime/build/import 依赖。

## 用户流程

1. 用户在 Kairos 对话中选择一张图片，可配文字，也可只发送图片。附件在发送前可预览、移除和重选。
2. 图片只用于当前请求；MIMO API key 留在后端。后端验证文件类型、签名、尺寸/像素和解码风险后，将图片作为 MiMo 当前轮多模态输入。
3. 模型把图片解析为零到多条刚性事件候选（标题、星期/日期、开始/结束时刻、地点、重复信息）；无法辨认的字段或图片并非课表时先追问，不编造。
4. 若图片明确为按星期重复的课表，但没有学期/系列开始和结束日期，助手先询问这两个日期。澄清期间图片只保留在当前浏览器会话内，必要时随澄清重发；完成后释放附件。
5. 服务端校验结构化候选并建立多候选未保存刚性草稿。用户请求导入时，API 只读查询本人、且仅限图片所表示日期范围内的刚性日程；确认清单显示现有重复/重叠信息，不能静默删项、合并或代用户选择。
6. 用户明确确认后，沿用现有原子草稿提交；图片识别、工具调用或模型文字均不构成确认。如果提交时有新发生活动冲突，先展示冲突；只有用户再次明确点击“接受冲突并保存”后，才携带服务端一次性确认令牌原子提交。

## 数据与安全边界

- 第一阶段一条消息最多一张图片，格式 JPEG/PNG/WebP。建议文件上限 10 MiB、解码像素上限 20 MP；超限或损坏时保留本地原文/附件并提示可恢复错误。
- 使用 MiMo-V2.6-Pro 支持的 Base64 image URL 方式，从后端调用；不将 key 发往浏览器。
- 原始图片/Base64/完整 OCR 内容不写入数据库、日志或对话历史；结构化识别候选会按现有机制暂存到未提交草稿表，正式日程只在用户确认后保存。图像将由用户主动发送到 MiMo 服务处理，上传前明确提示。
- 图片文字是不可信用户数据，不能覆盖系统提示、工具权限、owner 或确认要求。
- 模型只能给出结构化提议。服务端重验用户本轮存在图片导入意图、字段与范围、时区、数量上限及稳定 candidate ID；不开放任意 HTTP/数据库工具。
- 重复课表必须有明确的系列日期范围；当前草稿规则需要 `recurrence.ends_on`，图片未包含时不得自动猜学期长度。
- 读取已有刚性日程时使用后端当前用户 owner scope；范围来自识别/澄清出的图片日期，使用有上限的 occurrence 查询。只读结果仅用于确认单提示，不更改或排除事件。
- 识别/模型/网络失败时不返回“已添加”；留存当前浏览器附件以供重试，不提交任何事件。

## 接口与组件边界

- `AssistantChatRequest` 增加独立于文本历史的当前轮图片附件字段；对话历史只保留文本和安全的图片占位预览，不重复携带 Base64。
- `MimoToolModel` 支持当前用户消息的文本+image content parts。新增严格的多候选刚性草稿提议结构；后端按 `Candidate`/`RecurrenceRule` 校验。
- 前端 `Composer` 负责文件选择、预览、移除、失败保留；`sessionStore` 将一次性附件交给 API，并在澄清阶段只于内存中保留。
- 草稿确认单继续使用现有结构化卡片；查询到的相关刚性日程作为只读结果同时展示。
- OpenAPI 与生成 TypeScript 类型需同步更新；旧图片验证器若选择性迁入，需记录来源、hash、修改原因及新测试，不能直接 import 旧目录。

## 验收

1. JPEG/PNG/WebP 单图可上传、预览、移除；普通文本会话没有回归；超限、伪造 MIME、损坏及像素超限文件在进入模型前拒绝。
2. 假模型可从课表图片产生多条候选；模型无效结构、幻觉时间、无法辨认字段不能写入正式事件。
3. 按星期重复课表缺少系列日期时追问开始/结束日期；候选确认单保留所有识别行。
4. 显式图片导入只查询当前用户与图片日期范围内的刚性事件；重复和冲突被显示，工具不会替用户删掉、合并或选择任何一项。
5. 确认前正式事件数为零；用户显式确认后候选在一个事务中全部提交，失败时输入/附件/草稿仍可恢复。
6. 图片字节不进入 API 日志、对话历史或持久存储；需要真实 MiMo 图像请求时单独记录脱敏冒烟结果，不能用假模型测试冒充在线验收。
