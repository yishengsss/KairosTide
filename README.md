# KairosTide‑找回「时间之流」，重新栖居在时间里


> Time as the rhythm of the opportune, not the measure of the clock.
>
> **时间是时机的节律，而非钟表的度量。**

![image-1](https://github.com/yishengsss/xianaihack-GK024--/blob/main/KAIRSTID.png)
## 1. 项目概述
KairosTide‑找回「时间之流」，重新栖居在时间里是一款沉浸式时间体验系统。项目立足于对现代时间管理范式的反思，区别于传统日历、待办清单、专注计时类效率工具，不以时间刻度为核心驱动，而是借助动态自然场景重建人对时机的感知。

本项目思想溯源自古希腊时间哲学概念 `Chronos` 与 `Kairos`：`Chronos` 代表可计量、可切分的钟表刻度时间；`Kairos` 指代情境化的时机、时节。现代生活中标准化刻度时间占据主导地位，时机感知被不断弱化。**KairosTide‑找回「时间之流」，重新栖居在时间里**通过产品设计，重新赋予“时机”可被感知的地位，实现“不问几点，只问何时”的核心体验。

系统不将时间视作需要最大化利用的资源，而是将时间理解为人的生命体验本身，坚持低打扰的产品伦理，将行动选择权交还用户。

## 2. 核心设计理念
1. **去刻度优先**：数字时间不作为界面常驻信息，仅在用户主动查询时临时展示，避免刻度持续造成心理压力。
2. **区分约束与期许**：严格区分外部硬性约定与自我驱动类任务，差异化处理提醒逻辑，减少无意义精神内耗。
3. **工具的静默原则**：系统默认保持静默，仅在用户主动操作或客观事件发生时输出信息，不主动抢夺用户注意力。
4. **接纳有限性**：正视人的精力边界，允许部分安排自然错过，不因为任务未完成构建自我否定。

## 3. 系统主要功能与体验
### 3.1 沉浸式自然主场景
主界面为全屏动态自然山水场景，场景渲染受真实时间、季节、天气条件共同驱动。太阳轨迹、月相、星空、天空色调、水面反光、云层状态均实现连续平滑过渡，而非简单切换离散静态主题。

- 默认状态下界面不展示时钟、时间轴、倒计时、任务列表、完成率等信息；
- 用户长按主场景空白区域，临时调取并展示当前时间，数秒后自动淡出消失；
- 不存在“开启一天”“结束一天”业务流程；跨午夜仅更新环境渲染效果，不弹出新一天提示、日报或总结类弹窗。

### 3.2 双事件模型
系统将所有事件划分为刚性事件、柔性事件两类，两类事件拥有独立的生命周期与提醒策略。

#### 刚性事件
刚性事件指存在明确起止时刻的客观约定，例如课程、会议、预约，是唯一允许主动在主场景进行展示的事件类型，支持重复规则与单次例外处理。
1. 事件临近时触发可关闭提醒，提醒展示事件基础信息，不显示倒计时文本；用户确认“知道了”仅关闭本次提醒，不改变事件本身状态。
2. 到达事件实际开始时刻，事件信息柔和浮现；无用户操作即默认进入事件状态；事件结束后信息自然淡出，回归自由场景。
3. 针对重复事件，支持“本次请假”实例级例外操作，仅作用于单次事件，不修改整个重复系列。
4. 多个刚性事件发生时间冲突时，由用户选择当前展示对象；系统不会自动取消、删除任一事件。

#### 柔性事件
柔性事件为用户自我驱动类任务，可配置截止时间，无固定开始时刻，例如课程作业、自主学习任务。
1. 任务保存后后台静默存储，系统不会主动推送提醒。
2. 仅当用户主动发起查询时，AI助手才输出相关任务信息，可结合截止时间、当前状态评估紧迫程度。
3. AI不得自主创建任务，也不得自动为柔性任务分配具体时间。

### 3.3 自然语言驱动的事件管理
系统不提供独立的专门日程管理页面，事件的新增、修改、删除、请假、查询，主要通过AI自然语言对话完成。
1. 创建刚性事件会生成草稿对象，信息不完备时AI主动向用户澄清，不擅自推测时间、地点等关键字段；草稿必须经过用户确认才正式生效，未确认草稿不会参与提醒与状态计算。
2. 用户处于对话输入过程中，若刚性事件到达时间点，仅展示轻量化提示，禁止强制打断会话、清空输入内容；待用户退出对话面板后再切入事件场景。

## 4. 项目价值与意义
本项目属于反思性产品实践。当下绝大多数时间类工具以管控、优化、效率提升为目标，持续强化刻度时间对人的支配。**KairosTide‑找回「时间之流」，重新栖居在时间里**尝试提供另一种技术可能性：技术并非只能用来改造与逼迫人，也可以复原人的感官体验。

项目希望缓解刻度时间带来的焦虑，帮助使用者区分外界硬性义务与个人期许，降低工具带来的精神消耗，使人重新栖居于时序流动之中，而非持续被钟表数字支配。

## 5. 工程约束说明
1. 历史版本代码仅作为参考资料，前端进行完整重构；后端逻辑可评估后选择性复用，新旧代码目录隔离，旧版本业务逻辑不直接迁入新系统。
2. 视觉方案确定为写实自然山水风格，设计规范遵循 Apple‑design；项目采用 Harness Engineering 方式进行工程组织与任务分工。
3. 部分业务参数、第三方数据源、边界分支逻辑尚未完成决策，开发过程中不得自行扩展功能；严格禁止新增常驻时钟、倒计时、自动任务规划等不在需求范围内的特性。

> 愿景：愿你来时带着钟表，离开时与万物同频。
