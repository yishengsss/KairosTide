# API 自然语言事件意图分析

## 状态与范围

用户已确认：对用户表达的任务/安排，由后端 API 使用模型分析是否为固定时间任务，区分刚性事件/柔性事项；如果 AI 无法确定则先询问。结构化结果须经服务端校验，刚性事件只生成草稿，仍需用户确认后才能保存。

本次覆盖用户表达的任务/安排，包括“我10分钟后有个会，持续10分钟”及没有固定开始时刻的任务。修改范围限于 API 助手编排、刚性事件草稿解析及其测试；不改前端保存确认边界，不开放模型直接写数据库。

## 分类规则

- 对任务/安排表达，由模型分析语义并返回结构化类别：固定时间任务、柔性事项、需要澄清或非任务聊天。
- 明确固定开始时刻（包括“10分钟后”）的安排属于刚性事件。明确持续时长用于计算结束时刻；只有持续时长、没有固定开始时刻时不能据此判为刚性。
- 没有固定开始时刻的事项属于柔性事项；截止日期可以保留，但不得自动放入日程。创建仍须遵循用户添加柔性事项的既有权限规则。
- 任务类型、固定时间语义或必要字段无法由消息可靠确定时，先向用户追问；不由模型猜测并写入。
- “有个会”可提取为通用标题“会议”。缺失或歧义字段必须追问，不能由模型臆造。

## 数据流与权限

1. API 捕获一次服务端 `reference_now` 及用户时区，对用户表达的任务/安排通过 MiMo 做受限结构化意图分析；普通聊天维持回答。
2. 模型只返回分类提案、必要字段和澄清需求；它没有任意工具、HTTP、数据库或提交权限。
3. 服务端验证分类、时间表达、数值范围、时区和必需字段。相对时间从固定 `reference_now` 确定性计算，拒绝模型自行提供的“当前时间”。
4. 固定时间任务调用现有 DraftService 创建未提交草稿；符合用户添加意图的柔性事项继续走现有受限柔性任务流程；模型不明确或输入信息不足时返回具体追问。
5. 模型输出无效、字段不足、分类或关键字段无法由文本支持、服务不可用时不写业务事实；应澄清或返回诚实错误。
6. 只有前端显式确认仍可提交刚性草稿。模型分类、工具调用或自然语言“已安排”均不是用户确认；柔性事项仍受主动添加权限约束。

## 目标示例

输入：“我10分钟后有个会，持续10分钟”。服务端参考时刻为 `T` 时，得到刚性事件草稿：标题“会议”，`start_at = T + 10分钟`，`end_at = T + 20分钟`，用户时区明确；数据库中不出现正式事件，直到用户确认。

## 验收

1. 假模型将目标句分类为刚性，并提取 10 分钟相对开始与 10 分钟持续时间；固定时钟测试验证起止时间及草稿未提交。
2. 柔性描述（例如“周日前完成实验”）不被转换为固定事件；没有明确添加意图时不创建柔性事项。
3. 模型无法区分固定时间与柔性事项时，API 返回针对性的澄清问题，不猜测。
4. 查询、普通聊天、歧义时间、缺失字段、伪造时间和无效模型输出均不产生未授权写入。
5. 模型不可用时 API 不回退为伪造成功；既有草稿确认测试保持通过。
6. 若配置真实 MiMo，单独记录真实 API 冒烟结果；假模型测试不能代替真实模型表现证据。
