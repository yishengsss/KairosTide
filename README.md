## 1. 项目概述

KairosTide‑找回「时间之流」，重新栖居在时间里是一款沉浸式时间体验系统。项目立足于对现代时间管理范式的反思，区别于传统日历、待办清单、专注计时类效率工具，不以时间刻度为核心驱动，而是借助动态自然场景重建人对时机的感知。

本项目思想溯源自古希腊时间哲学概念 `Chronos` 与 `Kairos`：`Chronos` 代表可计量、可切分的钟表刻度时间；`Kairos` 指代情境化的时机、时节。现代生活中标准化刻度时间占据主导地位，时机感知被不断弱化。**KairosTide‑找回「时间之流」，重新栖居在时间里**通过产品设计，重新赋予“时机”可被感知的地位，实现“不问几点，只问何时”的核心体验。

系统不将时间视作需要最大化利用的资源，而是将时间理解为人的生命体验本身，坚持低打扰的产品伦理，将行动选择权交还用户。

## 2. 核心设计理念

1. **去刻度优先**：数字时间不作为界面常驻信息，仅在用户主动查询时临时展示，避免刻度持续造成心理压力。
2. **区分约束与期许**：严格区分外部硬性约定与自我驱动类任务，差异化处理提醒逻辑，减少无意义精神内耗。
3. **工具的静默原则**：系统默认保持静默，仅在用户主动操作或客观事件发生时输出信息，不主动抢夺用户注意力。
4. **接纳有限性**：正视人的精力边界，允许部分安排自然错过，不因为任务未完成构建自我否定。

## 3. 系统主要功能与体验

### 3.1 沉浸式自然主场景

主界面为全屏动态自然山水场景，场景渲染受真实时间、季节、天气条件共同驱动。太阳轨迹、月相、星空、天空色调、水面反光、云层状态均实现连续平滑过渡，而非简单切换离散静态主题。

- 默认状态下界面不展示时钟、时间轴、倒计时、任务列表、完成率等信息；
- 用户长按主场景空白区域，临时调取并展示当前时间，数秒后自动淡出消失；
- 不存在“开启一天”“结束一天”业务流程；跨午夜仅更新环境渲染效果，不弹出新一天提示、日报或总结类弹窗。

### 3.2 双事件模型

系统将所有事件划分为刚性事件、柔性事件两类，两类事件拥有独立的生命周期与提醒策略。

#### 刚性事件

刚性事件指存在明确起止时刻的客观约定，例如课程、会议、预约，是唯一允许主动在主场景进行展示的事件类型，支持重复规则与单次例外处理。

#### 柔性事件

柔性事件为用户自我驱动类任务，可配置截止时间，无固定开始时刻，例如课程作业、自主学习任务。

### 3.3 自然语言驱动的事件管理

系统不提供独立的专门日程管理页面，事件的新增、修改、删除、请假、查询，主要通过AI自然语言对话完成。

1. 创建刚性事件会生成草稿对象，信息不完备时AI主动向用户澄清，不擅自推测时间、地点等关键字段；草稿必须经过用户确认才正式生效，未确认草稿不会参与提醒与状态计算。
2. 用户处于对话输入过程中，若刚性事件到达时间点，仅展示轻量化提示，禁止强制打断会话、清空输入内容；待用户退出对话面板后再切入事件场景。

## 4. 项目价值与意义

本项目属于反思性产品实践。当下绝大多数时间类工具以管控、优化、效率提升为目标，持续强化刻度时间对人的支配。**KairosTide‑找回「时间之流」，重新栖居在时间里**尝试提供另一种技术可能性：技术并非只能用来改造与逼迫人，也可以复原人的感官体验。

项目希望缓解刻度时间带来的焦虑，帮助使用者区分外界硬性义务与个人期许，降低工具带来的精神消耗，使人重新栖居于时序流动之中，而非持续被钟表数字支配。

## 快速开始

需要 Python 3.11+、Node.js 和 npm。macOS/Linux 在项目根目录运行：

```bash
./start.sh
```

脚本会创建 API 虚拟环境，并在依赖缺失时安装根目录 [`requirements.txt`](requirements.txt) 和前端 `package-lock.json` 中的依赖，然后启动前后端。浏览器打开启动日志中 Vite 显示的地址，通常是 `http://127.0.0.1:5173/`；API 默认在 `http://127.0.0.1:8000/`。按 `Ctrl+C` 停止服务。

本地开发数据保存在 `var/kairos-dev.sqlite3`，重启服务后仍会保留。不要删除这个文件，除非你确实要清除本地日程和任务数据。

## 启用 MiMo 助手

复制 `.env.example` 为根目录 `.env`，在 `.env` 的 `MIMO_API_KEY` 中填写自己的密钥，然后重启服务：

```bash
cp .env.example .env
```

`.env` 已被 Git 忽略。密钥由后端读取，不会传给前端。没有配置密钥时，自然场景仍可打开，但 AI 对话功能不可用。也可以将 `MIMO_API_KEY` 留空并设置 `MIMO_API_KEY_FILE`，让后端从本地文件读取密钥。

## 页面使用

- **查看真实时间**：在自然场景的空白处按住，时间会短暂显示后淡出。点击按钮、事件提示或对话面板不会触发查时。
- **打开助手**：点击右下角“问 Kairos”。例如，可以请求记录一项待完成任务、查询已保存的柔性任务或固定日程，或用自然语言创建日程。固定日程会先生成待确认草稿，检查内容后再确认保存；修改或删除也会先显示提案供确认。
- **发送消息**：按 Enter 发送，Shift + Enter 换行。可以附加 JPEG、PNG 或 WebP 图片（最大 10 MiB）用于课表识别；图片仅供本轮处理，不作为 Kairos 的日程内容保存。
- **处理刚性事件**：提前提醒出现时，“知道了”会关闭本次提醒。事件正式开始后，可在事件卡点“知道了”将其收起为红圈；点击红圈可重新展开。点“例外”会直接对本次事件实例记请假，不经过 AI。
- **处理柔性任务**：已保存任务可能以无文字的黄色圆圈短暂出现在水面下方。点击可查看详情并选择接受；接受后圆圈会持续显示，之后可选择暂停或完成。它不是固定日程，也不会自动安排开始时间。

## 当前版本范围

主场景、长按查时、助手事件与任务操作、红黄圈交互已接入当前应用。真实浏览器端到端验收尚未完成；通过构建和自动测试不等于所有实际浏览器流程已验收。主页面的场景地点选择与真实天气展示也尚未接入，因此当前页面不会因为 README 或产品规划的描述就自动显示实时天气。

## 开发检查

依赖已安装时，也可以直接运行 `python3 scripts/dev.py`。常用检查需逐项运行：

```bash
python3 scripts/check.py docs
python3 scripts/check.py architecture
python3 scripts/check.py contracts
python3 scripts/check.py api
python3 scripts/check.py web
```

`python3 scripts/check.py e2e` 当前会报告 `NOT_RUN`，因为仓库还没有自动化浏览器旅程。
